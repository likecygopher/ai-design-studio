# 变更规格：企业单点登录 SSO（OIDC）

- 变更 ID：`CHG-2026-10-27-SSO`
- 目标：接入企业 IdP（Azure AD / Okta / Keycloak / Google Workspace 等 OIDC 提供商），员工用企业账号登录，自动关联/开通本地账号。

## 1. 配置（环境变量，服务端）

```env
SSO_ISSUER=https://login.microsoftonline.com/<tenant>/v2.0
SSO_CLIENT_ID=...
SSO_CLIENT_SECRET=...
SSO_NAME=企业 SSO
SSO_SCOPES=openid email profile
SSO_ALLOWED_DOMAINS=acme.com,example.com   # 可空=不限制
SSO_AUTO_PROVISION=true                    # false=仅允许已存在账号
SSO_DEFAULT_ORG_SLUG=acme                  # 可选：新用户自动加入组织
```

- 三项核心配置（issuer/clientId/clientSecret）缺一不可，否则 SSO 不启用；启动校验会提示成对配置。
- IdP 回调地址：`https://<你的域名>/api/auth/callback/enterprise-sso`，需在 IdP 注册。
- 使用 Authorization Code + PKCE + state/nonce（Auth.js OIDC Provider）。

## 2. 账号关联与开通

- `User` 新增 `ssoProvider` / `ssoSubject`（唯一索引，迁移 `20261027140000_sso_identity`）。
- 登录流程：
  1. IdP 回调 → 校验域名白名单；
  2. 按 `(provider, subject)` 找已有 SSO 账号；
  3. 否则按邮箱关联已有本地账号并写入 SSO 标识；
  4. 否则 `SSO_AUTO_PROVISION=true` 时创建账号（随机密码、默认 user 角色、个人组织）；
  5. 可选加入 `SSO_DEFAULT_ORG_SLUG` 组织并设为 active org；
  6. 创建 `AuthSession` 设备会话，JWT 写入用户/角色/authVersion/sessionId。
- 禁用账号、域名不符、未开通且关闭自动开通 → 登录失败并审计 `auth.login_failed`；自动开通审计 `auth.sso_provision`。
- 本地 TOTP 2FA 对 SSO 登录不做二次校验（由企业 IdP 的 MFA 负责）。

## 3. UI

- `/login` 在 SSO 启用时显示「使用企业 SSO 登录 · <SSO_NAME>」按钮（中英双语）；未配置时完全不显示。
- 登录页按运行时环境变量渲染（`force-dynamic`）。

## 4. 边界

- 当前为**平台级单 IdP** 配置；每组织独立 IdP/多租户 SSO 可在此之上扩展（组织级配置表 + 动态 issuer）。
- 未实现 SAML 2.0、SCIM 自动同步、组映射到角色；如需可后续增加。
- SSO 用户可继续使用个人 API Token/Webhook/组织能力。

## 5. 验收

1. 配置 OIDC 后登录页出现 SSO 按钮并跳转 IdP；回调后建立与密码登录一致的会话。
2. 已存在账号按邮箱关联；未知账号按开关自动开通或拒绝；域名/禁用校验生效。
