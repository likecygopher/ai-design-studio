# 工程宪法（SDD Constitution）

> 本文件是 ai-design-studio 平台的最高工程约束。任何规格、设计、实现与审查都必须满足本文件的门禁；违反即为缺陷，不是"取舍"。

## 1. 产品定位

- 平台面向美的海外营销团队，多用户并发使用，产出可用于商业素材评审的图片/视频内容。
- "商业级"定义：多租户数据隔离、可审计、可限流、可恢复、可观测、可部署、可回滚。
- 对外承诺的是**稳定性与边界**，不是"AI 一定能产出像素级完美素材"。提示词无法保证的内容不得写入验收标准。

## 2. 不可违背的原则

1. **数据隔离第一**：任何读写必须携带 `userId` 作用域（或经 `requireRole("admin")` 显式越权）。禁止出现无作用域的 `findFirst/findMany/update/delete`。
2. **默认拒绝**：路由默认需要认证；公开路由必须在 `middleware.ts` 或 `withPublic` 中显式声明并注明原因。
3. **不信任输入**：所有请求体、表单、文件名、URL、ID 均需校验；上传文件必须做魔数（magic bytes）校验，不能只信 `content-type`。
4. **失败可诊断**：所有错误响应携带 `code` 与 `requestId`；服务端日志为结构化 JSON 且做敏感字段脱敏。
5. **资源有上限**：用户并发任务数、单文件大小、单请求文件数、用户存储配额、限流阈值都必须可配置且有默认值。
6. **任务可恢复**：任何异步任务必须能重试、能取消、能被回收；worker 崩溃不得造成任务永久卡死。
7. **向后兼容**：既有 13 个前端工作流与 API 路径不得回归。新错误结构保留 `error: string` 字段。
8. **测试先行**：新增/修改行为必须先写失败测试（TDD）。纯 UI 样式调整可豁免，但需说明。
9. **可回滚**：数据库变更必须通过 Prisma migration，禁止手改生产库；每次 schema 变更必须可 `migrate deploy`。
10. **无密钥入库**：`.env*` 不入库；日志与错误不得回显 API Key、密码、Token。

## 3. 质量门禁（Definition of Done）

一个任务只有在以下全部通过后才算完成：

- [ ] `pnpm typecheck` 退出码 0
- [ ] `pnpm test` 全绿（含新增测试；基线遗留失败必须修复而非豁免）
- [ ] `pnpm build` 退出码 0
- [ ] 新增/修改的 API 有 401/403/400/429 边界测试
- [ ] 新增持久化字段有 migration
- [ ] 文档（`README.md` / `docs/runbook.md` / SDD 文档）同步
- [ ] 不引入未使用依赖；不修改与本任务无关的文件

## 4. 安全基线

- 认证：NextAuth v5 Credentials，JWT 会话，`AUTH_SECRET` ≥ 32 字符，启动校验。
- 密码：bcrypt cost ≥ 12，长度 8–72，必须同时含字母与数字。
- 会话：`maxAge` 7 天，`updateAge` 1 天；登出后 JWT 失效。
- 响应头：`nosniff`、`DENY` frame、`Referrer-Policy`、`Permissions-Policy`，生产环境 `HSTS`。
- 上传：仅允许 PNG/JPEG/WebP/PDF/MP4；拒绝 SVG（XSS 风险）；单文件 ≤ 30 MB。
- 越权：跨用户访问统一返回 404（不泄露资源存在性）。
- 平台密钥：管理员在界面配置的第三方密钥必须加密落库（AES-256-GCM），接口只返回掩码，日志/审计不得出现明文。
- 依赖：新增依赖需在 PR 说明理由；禁止引入未经审计的脚本包。

## 5. UI 文案原则

- 界面只保留**操作、状态、约束、错误与空态**；产品介绍、教学步骤、卖点宣传与免责声明不得出现在界面。
- 说明性内容放入 README / runbook / 帮助入口；需要时用默认收起的 `<details>` 承载。
- 约束类文案压缩为一行（例：`8 位以上，含字母与数字。`、`PNG / JPEG / WebP ≤30 MB`）。
- 装饰性英文眉标（`PRODUCT STICKER COMPOSITOR` 等）不作为界面元素使用。
- 危险操作必须保留明确后果（例：`重置后该用户需重新登录。`），这是产品要求而非说明文字。

## 6. 变更管理

- 分支：`main` 为唯一长期分支；功能分支 `codex/<slug>`。
- 提交：Conventional Commits（`feat:`/`fix:`/`chore:`/`docs:`/`test:`）。
- 每次提交后必须能独立通过质量门禁。
- 破坏性变更需在 `docs/sdd/specs/` 中新增 ADR 段落并说明迁移路径。
